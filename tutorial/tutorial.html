The Funnel Protocol

A complete webinar funnel — landing page, registration, upsell, nine personalised emails, pixel tracking — rebuilt for your niche without writing code.

Total time
~15 min
Lovable credits
1–2
Steps
6
Code written
None

Why it works this way

Worth thirty seconds, because it explains every odd instruction that follows.

Lovable charges credits per prompt. Building a funnel this size inside Lovable costs hundreds of credits and days of arguing with it about things it already got right.

So Lovable barely does anything here. It creates an empty project with a database, then hosts the result. Everything in between happens in GitHub, where Claude works for free. Claude edits GitHub, Lovable notices the change and redeploys itself.

KEY

Never ask Lovable to build a feature. If you find yourself typing a request into Lovable after step 1, stop — that is credits burning. Ask Claude instead.

Before you start

Five minutes of setup. Do these now so nothing blocks you mid-build.

  • A Lovable accountlovable.dev — the free tier is enough to begin.
  • A GitHub accountgithub.com — free. This is where your funnel actually lives.
  • Claude Code, installed and signed inConnect the same GitHub account you just made.
  • Your answers readyOpen intake/funnel-brief.md. You can answer live instead, but having it filled in halves the build time.
  • A domain, a webinar link, a Meta Pixel IDNot needed to build — needed to go live. Placeholders are used until you have them.

The procedure

Each card names the app you should be looking at. If you are in a different window than the card says, you are in the wrong place.

1
In Lovable2 min1–2 credits

Create an empty project

  1. Go to lovable.dev → New Project. Name it anything.
  2. Paste the prompt below and send it.
  3. Wait until it stops working. Roughly two minutes.
Paste into Lovable
Set up a bare skeleton only. Do not design anything. Do not write any copy,
styling, images, or components beyond what is listed here. I will build the
real thing outside Lovable.

1. Enable Lovable Cloud so the project has a database and edge functions.

2. Create these routes, each rendering only an <h1> with its own name and
   nothing else:
   /  /vip  /ip  /thank-you  /thanks  /thanksalot  /preferences
   /terms  /privacy  /refund  /disclaimer  /closed
   /replay1  /replay2  /replay3  /control-room  /win

3. Leave index.css and tailwind.config.ts at their defaults.

Stop after that. Do not add features, do not improve anything, do not
suggest next steps.
EXPECT

A plain page with one heading and no styling. That is correct. It is supposed to look unfinished — you are paying Lovable for a database, not a design.

2
In Lovable30 sec

Push it to GitHub

  1. Top right of Lovable → the GitHub button.
  2. Connect to GitHub → authorise → Create Repository.
  3. Copy the repository URL. It looks like github.com/yourname/your-project.
KEEP

Paste that URL somewhere you can find it. Step 4 needs it, and hunting for it later is the most common place people stall.

3
In Claude Code1 min

Connect Claude to the same GitHub

  1. Open Claude Code and sign in.
  2. Connect GitHub — the same account Lovable just pushed to.
  3. Confirm it can see the repository from step 2.
WATCH

If you have more than one GitHub account, this is where it goes wrong. Claude must be on the account that owns the new repository, not your older personal one.

4
In Claude Code30 sec to send

Hand Claude the build

Replace the line marked >>> with your own repository URL. Change nothing else — the rules underneath are what keep Claude from inventing your testimonials or leaking a key.

Paste into Claude Code
You are setting up a webinar funnel for me using The Funnel Protocol kit.

>>> MY REPO: https://github.com/PUT-YOURS-HERE/your-project

Do this in order and tell me when each step is done.

1. Make a folder at ~/Documents/Funnels/<repo-name> and clone my repo into it.
   If ~/Documents/Funnels does not exist, create it.

2. Clone the kit next to it, then read kit/blueprint/00-BUILD-ORDER.md before
   doing anything else. That file is the source of truth for the build.

3. Check my repo is what you expect: a Lovable skeleton with placeholder routes
   and a supabase folder. If it looks like something else, stop and tell me
   rather than guessing.

4. Interview me using kit/intake/funnel-brief.md. Ask in small batches, never
   more than five questions in a message. If I say I have already filled the
   brief in, read my copy and only ask about what is blank or contradictory.

5. Build the funnel per the build order. Write everything into MY repo, commit
   in logical chunks, and push when a stage is finished and building.

6. Generate SETUP.sql at the root of my repo and hand it to me as a file.

RULES, these matter more than being fast:
- Never tell me to run a prompt in Lovable to build something. Lovable only
  hosts. Every change is a file in GitHub.
- Never invent my numbers, testimonials, results, or credentials. If I have not
  given you a real one, use an obvious placeholder and add it to STILL-NEEDED.md.
- Never put an API key in any file that ships to the browser.
- Ask before anything that costs money or sends a real message to a real person.
- When you are unsure between two readings of what I said, ask.
5
In Claude Code10–15 min

Answer the questions

Claude asks in small batches. Answer in plain language — rough is fine, and it will tell you when something is missing rather than filling the gap itself.

TIP

Say "I don't have that yet" freely. It becomes a visible placeholder and a line in STILL-NEEDED.md. A funnel with three honest gaps ships; one with three invented testimonials is a problem you cannot see until someone else does.

It will stop and show you the config before building. Read it. Fixing a wrong headline there takes seconds; fixing it after nine emails quote it does not.

6
In Lovable2 min

Run the one SQL file

Claude hands you SETUP.sql. This builds your database — the tables that hold registrations, the email queue, your settings. It is one paste.

  1. In Lovable, open the backend / database panel → SQL editor.
  2. Paste the whole file.
  3. Click Run. If it warns about a destructive statement, that is the "remove the old version first" line. Run it anyway.
DONE

Your funnel is live. Open your Lovable preview URL.

FIRST

If email is the one that fails, it is almost always the sending domain. Email providers refuse to send from a domain you have not verified. Claude will tell you which records to add and where — it is a five-minute job, once.

When something goes wrong

In rough order of how often each actually happens.

Claude cannot find my repository

Nearly always the GitHub connection, not the URL. Check Claude Code is connected to the account that owns the repo — if you have a personal and a work account, it is usually on the wrong one. Reconnect, then paste the step 4 prompt again.

Lovable still shows the plain skeleton page

Lovable redeploys when GitHub changes, but not instantly. Give it two minutes, then hard refresh. If it is still bare, ask Claude "did you push?" — sometimes work is committed locally but not pushed, and nothing reaches Lovable until it is.

My emails are not arriving

Three causes, in order of likelihood. One: the sending domain is not verified with your email provider. Two: the scheduled job that sends queued email was never created — it is in SETUP.sql, so check that ran fully. Three: it sent and landed in spam. Check there before assuming it failed.

Claude wants me to run something in Lovable

Only ever for SETUP.sql in step 6. Anything else means it drifted from the build order. Reply: "No — make that change in GitHub instead." It will correct itself.

I ran out of Lovable credits

Then something asked Lovable to build. The whole design of this procedure is that steps 3–5 cost nothing. Check you did not paste the step 4 prompt into Lovable by mistake — it is long, and Lovable will happily try to act on it.

The funnel is built but numbers and quotes look fake

They are, deliberately. Open STILL-NEEDED.md in your project — every placeholder is listed there. Replace them with real ones and ask Claude to update the funnel. Do not launch ads until that file is empty.
